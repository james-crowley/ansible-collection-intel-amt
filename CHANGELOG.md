## v1\.0\.0

<a id="release-summary"></a>
### Release Summary

<strong>1\.0\.0\.</strong> The interfaces are now stable under semantic versioning\: option names\, return
structure and <code>error\_class</code> values will not change incompatibly inside 1\.x\.

What earned the version is evidence\, not features\. Every hardware qualification stage that
has evidence now has it on <strong>both</strong> lab machines — AMT <strong>16\.1\.30</strong> and <strong>19\.0\.5</strong>\, three
majors apart\. Stages 10\, 11 and 12 previously had machine\-1\-only results and were recorded
as explicit gaps\; they have now run on machine 2 \(pipeline 244\, jobs 3168/3170/3172\) and
those gaps are closed\. All seven modules have touched real firmware\.

<strong>The sleep/hibernate refusal now reproduces on both generations\.</strong> <code>sleep\-light</code>\,
<code>sleep\-deep</code> and <code>hibernate</code> are refused by firmware before the request reaches the
platform on 16\.1\.30 <em>and</em> 19\.0\.5\. It was a one\-machine finding at 0\.7\.0 and is now a
two\-generation one — the risk being that machine 2 accepted them and made the 0\.7\.0
documentation wrong in the other direction\. It did not\.

<strong>\`\`README\.md\`\` gains a single Known limitations section</strong>\, so a reader sees the current
limits in one place instead of reconstructing them from nine releases of <code>known\_issues</code>\.
It covers the sleep refusal\, the empty <code>CIM\_Card\.SerialNumber</code>\, <code>amt\_media</code>\'s inert
<code>validate\_certs</code>\, the five capabilities not built \(each tracked as an issue\)\, and what
hardware evidence cannot reach at all\.

<strong>What 1\.0 does not claim\.</strong> Not that every capability is proven everywhere\. All hardware
evidence comes from two Lenovo ThinkStation P3 Tiny units\, so two generations agreeing is
<strong>repeatability\, not a compatibility guarantee</strong>\. Six Tier 4 entries remain permanently out
of reach and say why — a non\-zero IDE\-R write needs an OS on the target that writes\, and
independent confirmation of physical power\-off cannot come from CI\, because two machines
self\-reporting <code>off</code> is the same kind of evidence rather than independent evidence\.

## v0\.7\.1

<a id="release-summary-1"></a>
### Release Summary

A bugfix release\, and every fix in it was found by <strong>real firmware or by adversarial
review</strong>\, not by writing more code\.

<strong>\`\`amt\_event\_log\`\` no longer counts empty log slots as records\.</strong> On a log with slots
freed by a previous <code>amt\_log\_clear</code>\, firmware returns a zero\-filled 21\-byte entry per
freed slot\, and this collection counted them\. On the lab machine that meant
<code>records\_read\: 223</code> against firmware\'s own <code>total\_records\: 18</code> — a module whose
accounting contradicted itself\, and whose <code>EXAMPLES</code> told callers to compare exactly
those two fields\. Now <code>records\_read\: 18</code> with the excluded entries reported separately
as <code>empty\_slots</code>\, confirmed on the same machine and the same log state that produced
the defect\.

Worth recording what this needed\: a <strong>cleared\-then\-partially\-refilled log</strong>\, a state that
only exists because a destructive stage ran first\. No mock produced it — the mock always
kept its counter and its records consistent\, which is exactly why nothing caught this
earlier\. There is now a mock knob that serves zero\-filled slots\, driven through the real
client\.

<strong>A scarier hypothesis was tested and refuted\.</strong> The leading explanation was that
<code>GetRecords</code> serves records <code>ClearLog</code> has deleted\, which would have made every
post\-clear read untrustworthy\. Zero of the archived pre\-clear records appear in the read\.
<code>docs/amt\_log\_clear\.md</code> now states positively that a post\-clear read is trustworthy\,
rather than staying silent and letting the suspicion be repeated as fact\.

<strong>The bare\-metal role\'s qualification summary no longer crashes</strong> against an older
<code>amt\_info</code>\, and the <code>default\(none\)</code> template guard now also catches <code>default\(0\)</code> —
measured\, because <code>0</code> round\-trips wrongly on ansible\-core ≤2\.18 exactly as <code>none</code>
does\, while <code>false</code>\, <code>\[\]</code> and <code>\{\}</code> round\-trip correctly and are deliberately not
flagged\.

<strong>A qualification stage now writes its evidence before asserting on it\.</strong> It previously
wrote evidence last\, so a failing assertion destroyed the artifact needed to diagnose it —
which is what happened here\, and cost a run to discover\.

<a id="minor-changes-1"></a>
### Minor Changes

* C\(amt\_event\_log\) \- new return value RV\(empty\_slots\)\: how many all\-zero C\(RecordArray\) entries firmware returned that the read excluded from RV\(records\)\. V\(0\) on a log firmware did not pad\. A non\-zero value is normal for a recently cleared log and is B\(not\) a fault\; notably it is also B\(not\) evidence that deleted records are being served\, since the entries are all zero and contain nothing that was in the log before the clear\. That distinction was tested rather than assumed \-\- none of the 205 records C\(ClearLog\) archived on C\(amt\-lab\-01\) appear anywhere in the read that followed it\, so M\(james\_crowley\.intel\_amt\.amt\_log\_clear\) needs no warning about post\-clear reads\.
* C\(tests/integration/mock\_servers/wsman\_server\.py\) \- new C\(AmtState\.message\_log\_empty\_slots\) knob \(and C\(\-\-message\-log\-empty\-slots\) on C\(run\_wsman\_mock\.py\)\)\: pad the C\(GetRecords\) response with N zero\-filled empty record slots after the real records\, B\(without\) counting them in C\(CurrentNumberOfRecords\)\. Nothing in this mock could previously make the container counter and the returned array disagree \-\- both were derived from the same list \-\- which is precisely why no test caught issue \#105 and only hardware did\. The padding string is derived from C\(bytes\(21\)\) \-\- the same primitive C\(message\_log\.\_EMPTY\_SLOT\_HEX\) is built from \-\- and separately confirmed to match the base64 C\(amt\-lab\-01\) actually sent\, rather than reverse\-engineered from the code that reads it\. Trailing placement only\, because that is where firmware put it\; the interleaved case is covered against a fake transport\, where it can be labelled constructed rather than served as evidence\. Driven through C\(message\_log\.read\_records\) over the real C\(WsmanClient\) and through the whole module in the C\(amt\_event\_log\) integration target\, with a response\-side C\(RecordArray\) counter and a C\(batches\) assertion as controls \-\- issue \#92\'s standard for a knob that is exercised rather than merely wired\.
* docs/amt\_event\_log\.md \- new \"Empty record slots are not records\" section\: what firmware does \(a zero\-filled 21\-byte entry per slot a C\(ClearLog\) freed\, uncounted in C\(CurrentNumberOfRecords\)\)\, and B\(exactly what a caller on 0\.7\.0 or earlier saw\) \-\- C\(records\_read\) larger than C\(total\_records\)\, which is the one comparison the same document tells you to use to detect truncation\; entries in RV\(records\) with no timestamp\, no entity\, no severity and no event data that decoded without error\; and any Jinja counting or grouping over RV\(records\) skewed by one entry per record the last clear archived\. Documents the new RV\(empty\_slots\) return value\, that a non\-zero value is normal rather than a fault\, that the sentinel test is all 21 bytes zero and nothing weaker\, and that the padding is measured on B\(one\) generation in B\(one\) log state with no source describing it anywhere \-\- which is why empty slots are skipped rather than treated as end\-of\-data\.
* docs/amt\_log\_clear\.md \- new \"A read after a clear is trustworthy \-\- this was tested\, not assumed\" section\. This module B\(deliberately does not gain\) a \"post\-clear reads are unreliable\" warning\, and the reason is stated positively\: that claim was measured and disproven\, so a warning would enshrine the refuted explanation as a caveat\. Also records the two practical consequences \-\- that RV\(records\_after\) was never exposed to the \#105 defect\, because it reads C\(CurrentNumberOfRecords\) from the log container rather than counting returned records \(firmware reported 18 while the read returned 223 entries\, and firmware was right\)\, and that a non\-zero RV\(empty\_slots\) on the next M\(james\_crowley\.intel\_amt\.amt\_event\_log\) read is expected after a clear\.
* docs/capability\-matrix\.md \- B\(record permanently that the scary hypothesis was refuted\.\) The leading explanation for the 205 was that C\(GetRecords\) serves records C\(ClearLog\) deleted\, which would have made every post\-clear read untrustworthy\, would have made stage 10\'s confirmation re\-read meaningless\, and would have needed a standing warning in M\(james\_crowley\.intel\_amt\.amt\_log\_clear\)\'s documentation\. B\(It was tested and disproven\)\: zero of the 205 pre\-clear archived records appear anywhere in the read\, and the padding entries are all zero and carry nothing that was in the log before the clear\. The mechanism is B\(padding\, not stale data\.\) The arithmetic that made it plausible is recorded alongside the refutation rather than dropped \-\- C\(records\_read \- total\_records\) \= 223 \- 18 \= 205\, exactly the archived count\, reproduced twice \-\- as a coincidence of the padding count necessarily equalling the freed\-slot count\. Written up plainly and in the tier document rather than only in a commit message\, because a refuted hypothesis that is never written down gets repeated as fact\.
* docs/capability\-matrix\.md \- record issue \#105 as what it is\: a <strong>Tier 3 success</strong>\. Stage 9 on C\(amt\-lab\-01\) \(AMT 16\.1\.30\, CircleCI job B\(2976\)\, evidence C\(amt\-lab\-01\-qualify\_event\_log\.json\)\) read B\(223\) records against C\(total\_records\: 18\) and B\(found a real defect\) \-\- C\(amt\_event\_log\) was counting firmware\'s zero\-filled empty record slots as records\. The 223 collapse to 13 distinct values\: 9 appearing once\, 3 appearing three times\, and one all\-zero record repeated B\(205\) times\, so 9 \+ \(3 x 3\) \= 18 and B\(firmware\'s counter was correct\)\. Recorded as the seventh row of the hardware\-defect table at the top of the document\, because no unit or mock test could have produced it\: the mock derived both the C\(GetRecords\) record array B\(and\) the container\'s own C\(CurrentNumberOfRecords\) from one list\, so the two could not disagree there\, and the defect is only visible when they do\. The event\-log B\(decode\) is unaffected and stays hardware\-proven on both generations \(205 records on 16\.1\.30 in pipeline 208\, 110 on 19\.0\.5 in pipeline 226\)\; what was wrong is B\(accounting\)\, not decoding\, and that distinction is stated rather than left for a reader to infer\.

<a id="bugfixes"></a>
### Bugfixes

* \.gitignore \- ignore C\(\.ansible/\)\, which C\(ansible\-lint\) materialises locally to make the checkout resolvable as its own collection \(the same symlink the CI lint job creates\)\. Untracked and unignored\, it showed up as a pending change and drew C\(yamllint\) into scanning a copy of C\(changelogs/changelog\.yaml\) through the symlink\.
* C\(amt\_event\_log\) \- empty slots are B\(skipped\)\, not treated as end\-of\-data\. On C\(amt\-lab\-01\) the 205 padding entries were contiguous and strictly trailing\, so stopping at the first one would have been correct there too \-\- and would have saved nothing\, because firmware had already set C\(NoMoreRecords\) in that same batch\. It was not adopted because no source describes this padding at all\: \"padding is always trailing\" rests on one firmware in one state\, and a generation that interleaved a freed slot between live records would have every record after it silently discarded under C\(complete\: true\)\, which is the exact defect in the prior art this module exists to avoid\. Skipping costs one wasted decode per slot and can never lose a record\.
* C\(amt\_event\_log\) \- stop counting zero\-filled empty log slots as records\. Real firmware pads its C\(GetRecords\) response with all\-zero 21\-byte entries for record slots a previous C\(ClearLog\) freed\, and this module counted them\, so RV\(records\_read\) could exceed RV\(total\_records\) and RV\(records\) carried entries with no timestamp\, no entity\, no severity and no event data\. Measured on C\(amt\-lab\-01\) \(AMT 16\.1\.30\, CircleCI job 2976\)\: one C\(GetRecords\) call returned B\(223\) C\(RecordArray\) elements while C\(AMT\_MessageLog\.CurrentNumberOfRecords\) reported B\(18\) and C\(NoMoreRecords\) was already set\. The 223 collapse to 13 distinct values \-\- 18 real records\, then one identical all\-zero record repeated B\(205\) times\, one per slot a clear earlier the same day had freed\. Firmware\'s counter was correct throughout and is not adjusted\; RV\(records\_read\) is\. The new RV\(empty\_slots\) reports how many entries were excluded\, so the padding stays visible rather than merely vanishing \(issue \#105\)\.
* C\(amt\_event\_log\) \- the sentinel test is B\(all 21 bytes zero\) and nothing weaker\, which is a deliberate choice with a cost attached\. A record whose timestamp is V\(0\) but whose other fields are populated is a firmware RTC fault an operator wants to see\, not padding to discard\, and is still returned with RV\(records\[\]\.timestamp\_utc\) as V\(null\)\. An all\-zero record of any B\(other\) length is also still returned\, because an unexpected record length is itself a finding and no source describes what a record longer than C\(MaxRecordSize\) holds\. A record that failed to decode is never treated as an empty slot \-\- \"we could not read these bytes\" is not \"we read them and they were empty\"\.
* scripts/check\-default\-none\-template\.sh \- widen the guard to also flag the bare\-int shape C\(\{\{ \.\.\. \| default\(0\) \}\}\) \(optionally with a trailing C\(\, true\)\)\, not only C\(default\(none\)\)/C\(default\(None\)\)\. Measured on ansible\-core 2\.17\.14 through 2\.21\.x\: C\(default\(0\)\) round\-trips through a quoted scalar exactly like C\(default\(none\)\) does \-\- C\(\"0\"\) \(str\) on \<\= 2\.18\, C\(0\) \(int\) on \>\= 2\.19 \-\- by the identical mechanism \(Ansible\'s C\(convert\_data\) does not evaluate a bare int back from text either\)\. C\(default\(false\)\)/C\(default\(\[\]\)\)/C\(default\(\{\}\)\) were measured to round\-trip correctly on every floor from 2\.17\.14 through 2\.21\.x and are deliberately NOT flagged\, and the separate C\(default\(X\, true\)\)\-treats\-falsy\- as\-missing hazard \(not a version\-floor divergence\; it reproduces identically on every floor\, and is too semantic to flag mechanically without a high false\-positive rate against the many correct C\(default\(omit\, true\)\) call sites in this repo\) is documented as an explicit boundary in the script\'s header instead of mechanically checked\. Widening found exactly one existing instance \(C\(tests/integration/targets/amt\_baremetal\_install\_role/files/nested\_play\.yml\)\'s C\(serial\:\)\)\, confirmed harmless \(Ansible\'s C\(serial\:\) keyword parses C\(\"0\"\) and C\(0\) identically on every floor\) and excused with the existing inline C\(\# default\-none\-reviewed\:\) marker\.
* tests/hardware/qualify\_event\_log\.yml \- write the evidence artifact B\(before\) the assertions rather than after them\. The stage recorded evidence as its last task\, so a failing assertion aborted the play and destroyed the artifact needed to diagnose it\. That is not hypothetical\: on C\(amt\-lab\-01\) in CircleCI pipeline 226 the accounting assertion fired \(C\(records\_read\=223\) against C\(total\_records\=18\)\, issue \#105\)\, and the 223 records that would have identified B\(which\) number was wrong were never written\, so a second run was needed to learn only that the numbers reproduce\. The evidence for a failure is worth more than the evidence for a pass\, and ordering it last guaranteed only the latter was kept\.
* tests/hardware/qualify\_readonly\.yml \- fix a pre\-existing crash in the \"Require the read outcomes and the fact values to agree\" task\, introduced in \#85 \(the commit that fixed the 0\.6\.0 qualification\-summary bug\)\. It built C\(amt\_hw\.operation\.hardware\_reads\) with no default\, so against an C\(amt\_info\) older than 0\.6\.0 the whole block raised out of the template engine before any of its conditions ran\, including the one written to name exactly that case\. Fixed the same way PR \#102 fixed the equivalent line in the census task\, C\(\| default\(\{\}\, true\)\)\, and factored the whole hardware\-summary task list out into C\(\_qualify\_readonly\_hardware\_summary\.yml\) so it can be driven directly by a new local\-only regression test \(C\(tests/hardware/test\_qualify\_readonly\_legacy\_shape\.yml\)\, now wired into CI\) against a synthetic pre\-0\.6\.0 C\(amt\_hw\) shape\, rather than only ever being exercised by real hardware on the path a run happens to take\.

<a id="v0-7-0"></a>
## v0\.7\.0

<a id="release-summary-2"></a>
### Release Summary

The release where the evidence caught up with the code\.

<strong>Four hardware stages ran against real firmware for the first time</strong>\, on <code>amt\-lab\-01</code>
\(AMT 16\.1\.30\)\. <code>amt\_event\_log</code> read <strong>205 records</strong> with no decode errors\, confirming
the 21\-byte record layout and that this collection\'s <code>GetRecords</code> iteration is accepted
as issued\. <code>amt\_log\_clear</code> cleared the log and an <strong>independent re\-read</strong> confirmed it
empty — verified by a separate read rather than by trusting the method\'s own return\.
Wake\-while\-powered\-off answered WS\-Man on <strong>three probes out of three</strong> while AMT reported
the machine off\, and accepted a wake request\. All seven modules have now touched real
firmware\.

<strong>The most important result is a negative one\.</strong> All three of <code>amt\_power</code>\'s sleep and
hibernate actions — <code>sleep\-light</code>\, <code>sleep\-deep</code>\, <code>hibernate</code> — were <strong>refused by
firmware</strong> on that machine\, before the request ever reached the platform\. The CIM codes
are correct and unchanged\; the finding is about firmware acceptance\. It is recorded in
<code>known\_issues</code> and in the module\'s own documentation rather than buried\, because a
caller reading the option list should learn it before trying it\. Scope honestly\: one
machine\, one firmware version\, and <code>amt\-lab\-02</code> has never been asked\.

<strong>Evidence artifacts now carry a SHA\-256 manifest</strong>\, computed after redaction and before
publication\, so a Tier 3 citation can be bound to the bytes a reader actually fetches
rather than only to a run that happened\. The four older runs remain permanently
digest\-less\; nothing can fix that retroactively\.

<strong>A production bug on the declared floor is fixed\.</strong> The <code>amt\_baremetal\_install</code> role
could not run at all on ansible\-core 2\.17 with stock ports\, and separately its
<code>password</code> and <code>tls\_fingerprint</code> guards used <code>is not none</code>\, which an empty string
passes — so on 2\.17 the requirement for an explicit TLS pin did not fire\. Both fixed\, and
the guard change is version\-independent hardening rather than a 2\.17 workaround\.

<strong>Two over\-redaction defects</strong> were found by reading published artifacts rather than by
looking for bugs\: <code>operation\.action</code> and the prose <code>note</code> fields were being rewritten
as fake hostnames\. Over\-redaction is harder to notice than a leak\, because the output
looks correct\.

### Breaking Changes / Porting Guide

* <code>amt\_baremetal\_install</code> role \- C\(amt\_baremetal\_install\_handoff\_host\) no longer defaults to C\(amt\_baremetal\_install\_host\) and is now required whenever C\(amt\_baremetal\_install\_wait\_for\_handoff\) is true \(which is the default\)\. A play that relied on the old default now fails in C\(tasks/validate\.yml\) before anything is contacted\, rather than after the reset\. To restore the previous behaviour exactly\, set C\(amt\_baremetal\_install\_handoff\_host\: \"\{\{ amt\_baremetal\_install\_host \}\}\"\)\; for a conventional inventory the intended value is usually C\(\"\{\{ inventory\_hostname \}\}\"\)\; or set C\(amt\_baremetal\_install\_wait\_for\_handoff\: false\) to skip the hand\-off wait entirely\. Callers that already set the variable\, or that disable the wait \-\- including both hardware qualification stages that drive this role \-\- are unaffected\.
* amt\_media \- C\(attach\_timeout\) is now an attach B\(deadline\) rather than an early\-confirmation bound\. An attach that reaches the timeout with the daemon still alive but no V\(attached\) verdict now B\(fails\) with C\(error\_class\=timeout\) and C\(indeterminate\=true\)\; it previously returned B\(success\) with C\(session\_state\=starting\)\. The old behaviour was documented as intended \-\- C\(docs/amt\_media\.md\) said such an attach \'is not reported as a failure\' \-\- so this reverses stated intent deliberately\, and is called out here rather than buried in bugfixes\.
* amt\_media \- the practical impact is on a genuinely slow endpoint whose attach used to exceed the default 10\-second C\(attach\_timeout\) and still work\. That case now fails\. B\(Raise C\(attach\_timeout\)\) rather than treating an unconfirmed attach as a success\: a caller that acts on the old receipt arms a one\-time boot and resets the machine into media that was never confirmed to be redirected\, which is the worst outcome available to a module that serves boot media\.

## v0\.3\.1

<a id="release-summary-6"></a>
### Release Summary

Patch release\, and worth taking if you read <code>amt\_info</code>\'s
<code>amt\.network\.wake\_on\_lan\_capable</code> on 0\.2\.0 or 0\.3\.0 — <strong>it returned the inverse

The <code>LinkPolicy</code> value table was taken from a third party\'s constants file and
three of its five entries were wrong\. The authoritative values are <code>1</code> \= S0 AC\,
<code>14</code> \= Sx AC\, <code>16</code> \= S0 DC\, <code>224</code> \= Sx DC\; there is no \"always on\" value\.
Because <code>14</code> was mislabelled and <code>16</code> was believed to be a wake bit\,
<code>wake\_on\_lan\_capable</code> tested for \"reachable while on battery\" and reported
<code>false</code> for desktops that are in fact reachable while powered off\.

<code>link\_policy\_names</code> values change accordingly\, and <code>wake\_on\_lan\_capable</code> now
reports <code>null</code> rather than <code>false</code> when firmware does not expose <code>LinkPolicy</code>
at all — \"firmware did not say\" and \"the link will not stay up\" are different
diagnoses\, and only the second explains why a remote power\-on cannot reach an
endpoint\.

No other module is affected\, and no return key was added or removed\.

## v0\.3\.0

<a id="release-summary-7"></a>
### Release Summary

Additive release\. No return shape from 0\.2\.0 changed\, so this is a drop\-in upgrade\.

<strong>Two new modules\.</strong> <code>amt\_event\_log</code> reads the firmware event log\, which is the
only place that records <em>why</em> an unattended install failed — boot failures\,
watchdog expiry\, power events the operating system never saw\. <code>amt\_log\_clear</code>
clears it\, so a log read after an install contains only that install\. Clearing is
irreversible and therefore requires explicit confirmation\.

The 21\-byte record layout is decoded rather than guessed\: two independent
implementations agree byte\-for\-byte\, a captured firmware record with its
Intel\-authored expected decode confirms it\, and the timestamp byte order was
checked arithmetically\. Five byte fields are deliberately left undecoded because
no table exists for them\, and raw bytes ship on every record so a wrong decode on
an unseen firmware generation stays diagnosable\. <code>docs/protocol\-notes\.md</code> §2\.8
records per fact which source established it and what remains inferred\.

<strong>Neither new module has been exercised against real firmware\.</strong> No hardware stage
covers them\.

<strong>What did move to hardware\-verified\:</strong> both lab machines have now completed all
eight qualification stages\, across AMT <strong>16\.1\.30</strong> and <strong>19\.0\.5</strong>\, so power
control\, IDE\-R media\, the writable\-image path and native one\-time PXE are no longer
a single\-machine result\. Every <code>amt\_info</code> fact added in 0\.2\.0 also came back
populated on both generations\, which retires the caveat that they rested only on a
third party\'s AMT 10\.0\.56 dump\.

<strong>A data\-exposure fix worth reading if you run the hardware suite\.</strong> Evidence
artifacts carried the endpoint address\, gateway\, MAC\, DNS servers\, management
domain\, platform GUID and username in the clear\. CircleCI masks context values in
log output but <em>not</em> in stored artifacts\, so holding those values as secrets did
not protect them\. <code>tests/hardware/redact\-evidence\.py</code> now redacts them before
publication\, using stable pseudonyms so records stay correlatable\, while preserving
the diagnostic substance\. It is verified against real evidence\, not only unit tests\.

Also fixed\: the hardware workflow could not launch at all — a bash here\-string was
parsed as an unclosed CircleCI parameter tag\, which <code>circleci config validate</code>
does not catch\, and because that workflow is only reachable via a pipeline
parameter the break survived two releases\. A guard script now fails the lint job on
any stray double angle bracket\.

### Release Summary

Additive release\. Nothing in 0\.1\.0\'s return shapes changed\, so this is a drop\-in

<code>amt\_info</code> gains network\, system\-state and BIOS facts\, most usefully the

reuse authorised and attributed in <code>NOTICE</code>\)\. What was taken is protocol facts
from that project\'s hardware research notes \-\- property names and values dumped
from a real AMT 10\.0\.56 machine \-\- and not code\. They are therefore recorded as
Tier 2 in <code>docs/capability\-matrix\.md</code>\: mock\-tested here\, resting on someone
else\'s hardware\, and <strong>unverified on AMT 16\.1\.30 or 19\.0\.5</strong>\, the two generations
every hardware\-qualified fact in 0\.1\.0 rests on\. The same applies to the three new
power actions\, which additionally depend on target\-OS ACPI support\.

Deliberately not adopted from that audit\: its network\-settings\, TLS\-config and
user modules\. <code>docs/capability\-matrix\.md</code> records why\, and the short version is
that each is either a non\-functional stub or capable of stranding the management
path in a way only a physical MEBx visit recovers\.

<a id="breaking-changes--porting-guide-1"></a>
### Breaking Changes / Porting Guide

* amt\_boot\, amt\_redirection\, amt\_media \- the <code>intel\-amt\-operation/v1</code> receipt \(<code>schema</code>\, <code>action</code>\, <code>endpoint</code>\, <code>previous</code>\, <code>desired</code>\, <code>observed</code>\, <code>tls\_peer\_fingerprint</code>\, and the success\-path <code>error\_class</code>\) is now nested under an <code>operation</code> key on every module\, matching the shape <code>amt\_power</code> already used\. It was previously spread directly at the top level of these three modules\' results\, which meant a caller could not write one helper that reads <code>error\_class</code>/<code>tls\_peer\_fingerprint</code> from any module in the collection \-\- exactly the defect tracked as issue \#22\. Module\-specific return values \(for example <code>amt\_boot</code>\'s <code>device</code>/<code>boot\_config\_selector</code>/<code>boot\_source\_selector</code>\, <code>amt\_redirection</code>\'s <code>supported</code>/<code>enabled</code>/<code>transport\_reachable</code>\, and <code>amt\_media</code>\'s <code>session\_id</code>/<code>session\_state</code>/<code>devices</code>/<code>bytes\_read</code>/<code>bytes\_written</code>\) are unaffected and remain at the top level\. A failed module\'s result is unaffected by this change\: <code>error\_class</code> still surfaces at the top level of <code>fail\_json</code>\, since that is what Ansible itself surfaces and what rescue blocks read via <code>ansible\_failed\_result\.error\_class</code>\.
* amt\_info \- now returns a non\-secret <code>intel\-amt\-operation/v1</code> receipt under an <code>operation</code> key\, for parity with the other four modules\. It is read\-only \(<code>operation\.action</code> is always <code>get\_facts</code>\, <code>operation\.changed</code> is always <code>false</code>\)\, and <code>operation\.previous</code>/<code>operation\.desired</code>/<code>operation\.observed</code> are always <code>null</code> \-\- a read has no prior\, intended\, or separately\-observed state to report beyond what the existing <code>amt</code> return key already carries\.

<a id="security-fixes-1"></a>
### Security Fixes

* CI \- move the self\-hosted lab runner\'s hardware\-qualification virtualenv off ansible\-core 2\.17 and onto <code>ansible\-core\~\=2\.18\.18</code>\. The 2\.17 line is affected by GHSA\-w8p5\-mx5w\-cpqj \[HIGH\] \-\- argument injection in <code>ansible\-galaxy role install</code> leading to arbitrary code execution \-\- and that line is EOL\, so no 2\.17 release will ever carry the fix\. 2\.18\.18 is the first release that does\. The pin had been held at 2\.17 only because the runner host had nothing but Python 3\.10 and ansible\-core 2\.18\+ requires 3\.11\+ on the controller\; the host now has Python 3\.12\, so the blocker is gone rather than merely accepted\. Nothing changes for consumers \-\- <code>requires\_ansible</code> stays at <code>\>\=2\.17\.0</code>\, which is a floor and not a pin\.
* IDE\-R write payloads are bounded against the transfer length declared by the WRITE CDB\, and MediaImage refuses any write that would extend the backing file\. Previously a host could declare a small write\, pass the bounds check\, then stream unbounded DATA\_FROM\_HOST frames at an advancing offset and grow a local file \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14)\)\.
* The insecure\-transport gate is enforced in the <code>WsmanClient</code> constructor rather than only in the convenience classmethod\, so plaintext WS\-Man cannot be selected without explicitly setting <code>allow\_insecure\_transport\=true</code> regardless of which entry point is used \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/12](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/12)\)\.
* The redirection session refuses to downgrade to cleartext or cnonce\-less digest authentication\, and verifies a pinned TLS leaf certificate before transmitting any bytes \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14)\)\.
* amt\_media \- decide attach failure from whether the session daemon is still alive\, rather than from whether it managed to write an error state before the timeout\. Only an explicit error state used to fail the module\, so a daemon killed during the digest handshake \-\- which is exactly what bad credentials cause \-\- could fall through to a success receipt depending on timing\. A failed attach reporting success is the worst available outcome for a module whose job is to serve boot media \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/44](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/44)\)\.
* amt\_media \- require O\(tls\_fingerprint\) when O\(use\_tls\=true\)\, and reject O\(ca\_path\) outright\. The redirection plane is a raw TLS socket whose only trust mode is leaf pinning\; TLS without a pin is encrypted but unauthenticated\, and silently ignoring a supplied ca\_path would leave an operator believing the session was chain\-validated \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20)\)\.
* amt\_media \- session state files are created mode 0600 rather than at the umask default\, so they are not readable by other local users even when the runtime directory already exists with laxer permissions \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20)\)\.

Real AMT 16\.1\.30 rejects <code>CIM\_BootConfigSetting\.ChangeBootOrder</code> carrying an empty <code>\<Source/\></code> with HTTP 400 and \"The supplied SOAP violates the corresponding XML schema definition\"\, because <code>Source</code> is typed as an endpoint reference and so requires child elements\. This blocked IDE\-R and BIOS boot entirely against real firmware\.
* README \- fix the unattended\-install example playbook referencing C\(media\.operation\.session\_id\)\, which does not exist\: M\(james\_crowley\.intel\_amt\.amt\_media\) returns RV\(session\_id\) at the top level of its result\, not nested under an C\(operation\) key \(that nesting is specific to M\(james\_crowley\.intel\_amt\.amt\_power\)\)\. * <code>PowerAction</code> keeps <code>StrEnum</code> semantics via an explicit <code>\_\_str\_\_</code>\. A plain <code>\(str\, Enum\)</code> renders as <code>PowerAction\.ON</code> under <code>str\(\)</code> and f\-string interpolation rather than <code>on</code>\, which would have silently changed the shape of messages and receipt fields\.
* amt\_baremetal\_install \- <code>amt\_baremetal\_install\_host</code> no longer defaults to <code>inventory\_hostname</code>\. AMT answers on a separate management address from the operating system\'s hostname\, so that default silently pointed at the wrong endpoint or an unresolvable name\; it now resolves from <code>amt\_host</code> and otherwise stays unset so validation fails loudly\.
* amt\_baremetal\_install \- choose the power transition from the observed power state instead of always issuing <code>reset</code>\. A master bus reset does nothing to a machine that is already off\, so installing an operating system onto a powered\-off machine \-\- arguably the common bare\-metal case \-\- attached the media\, armed the one\-shot boot\, and then reported success having booted nothing\.
* amt\_baremetal\_install \- connection variables now fall back to the conventional <code>amt\_\*</code> inventory variables \(<code>amt\_host</code>\, <code>amt\_password</code>\, <code>amt\_tls\_fingerprint</code> and friends\) that this collection\'s README\, docs and example inventory all use\, so a conventional inventory drives the role with no per\-variable mapping\.
* amt\_info \- read the system UUID from <code>CIM\_ComputerSystemPackage\.PlatformGUID</code>\. It was read as <code>UUID</code> from <code>CIM\_ComputerSystem</code>\, which has no such property\, so it was null on every endpoint and silently disabled the identity cross\-check that guards against acting on the wrong machine \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/30](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/30)\)\.
* amt\_info \- render the system UUID in the canonical dashed form\, reversing the first three SMBIOS fields\. <code>PlatformGUID</code> arrives as 32 undashed hex characters with those fields little\-endian\, so the naive reading produces a plausible\-looking UUID that does not match what MEBx displays \-\- which would make the identity cross\-check fail against a correctly recorded expectation \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/32](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/32)\)\.
* amt\_info \- report the AMT firmware version from <code>CIM\_SoftwareIdentity</code> \(the instance whose <code>InstanceID</code> is <code>AMT</code>\, read from <code>VersionString</code>\)\. It was previously read from <code>AMT\_GeneralSettings\.Version</code> and <code>AMT\_SetupAndConfigurationService\.VersionsSupported</code>\, neither of which exists\, so the reported version was always null \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/18](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/18)\)\.
* amt\_info \- stop reading <code>CIM\_ComputerSystem</code> during facts gathering\. It existed only to source the UUID and contributed nothing else\, so removing it also saves a WS\-Man round trip per call\.
* amt\_power \- correct the documentation example\, which used <code>state\: on</code>\. YAML parses an unquoted <code>on</code> as the boolean <code>true</code> rather than the string <code>\"on\"</code>\, so anyone copying the example would have passed the wrong type and failed argument validation\.

* tests/hardware/qualify\_power\.yml \- restore the starting power state using <code>previous\_state</code>\, the key <code>amt\_power</code> actually returns\. It referenced a non\-existent <code>power\_state</code> key\, so the guard always evaluated to <code>unknown</code>\, the restore silently skipped on every run\, and the stage reported that it had left the machine as\-is\. An assertion now fails loudly if the starting state cannot be read\.
* tests/hardware/qualify\_readonly\.yml \- surface the redacted failure detail when amt\_info fails\. The task carries <code>no\_log\: true</code> to keep task arguments \(including the password\) out of the log\, but that also censored the module\'s own error\, which errors\.py has already redacted and which is therefore safe to show\. A censored failure is undiagnosable\, so a rescue now reports <code>error\_class</code>\, <code>endpoint</code>\, <code>operation</code>\, <code>indeterminate</code> and the redacted message\.
* tests/hardware/qualify\_writable\_image\.yml \- pass the full connection options when re\-reading a media session\'s byte counters\. The call omitted <code>tls\_fingerprint</code> and the redirection port\, so it failed with <code>error\_class\=tls\_validation</code> after the writable\-device assertion had already passed\.
* tests/hardware/render\-inventory\.sh \- emit credentials as <code>lookup\(\'ansible\.builtin\.env\'\, \.\.\.\)</code> expressions instead of literal values\, so the AMT password and TLS fingerprint never touch disk\. Also accept <code>AMT\_HOST</code>\, <code>AMT\_PORT</code> and <code>AMT\_REDIRECTION\_PORT</code>\, matching the variables the lab context provides\.
* tests/hardware/render\-inventory\.sh \- emit the <code>amt\_targets</code> group the qualification playbooks actually target\. It previously emitted <code>amt\_lab</code>\, so every play would have matched zero hosts and reported success having done nothing\.
* tests/integration/mock\_servers/wsman\_server\.py \- AMT\_BootCapabilities now answers Enumerate as well as Get\. amt\_boot\'s discover\_and\_validate\(\) and redirection\_service\.py\'s get\_capabilities\(\) both reach it via Enumerate\+Pull \(it has no natural instance key for a Get SelectorSet\)\; the mock only implemented the Get form used by amt\_info\'s facts\-gathering path\, which every prior unit test masked by mocking WsmanClient\.enumerate\(\) directly instead of exercising this server \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/8](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/8)\)\.
