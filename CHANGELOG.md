## v0\.1\.0

<a id="release-summary"></a>
### Release Summary

First release\. Manages Intel AMT / vPro endpoints from Ansible\: capability
discovery\, power control\, one\-time boot selection\, redirection\-service state\,
and native IDE\-R virtual media — a bootable ISO and a writable image served to a
machine\'s firmware without shelling out to MeshCmd or Node\.js\.

Qualified against two physical machines running Intel AMT 16\.1\.30\, through all
seven hardware stages\: read\-only facts\, check\-mode plans\, power on/off\, IDE\-R
media attach and boot\, a writable image\, native one\-time PXE\, and an idempotent
re\-probe\.

See <code>docs/capability\-matrix\.md</code> for what is verified against real firmware\,
what is only covered by mock fixtures\, and what remains unproven\. That
distinction is maintained deliberately\, and the \"still unproven\" list is short
and specific rather than absent\.

* amt\_boot \- new module that arms a one\-time boot device selection \(<code>pxe</code>\, <code>hdd</code>\, <code>cd</code>\, <code>bios</code>\, <code>ider\_floppy</code>\, <code>ider\_cdrom</code>\) using the exact five\-step <code>AMT\_BootSettingData</code> / <code>CIM\_BootConfigSetting</code> / <code>CIM\_BootService</code> sequence documented in this collection\'s protocol notes\, with mandatory discovery before any mutation and a required per\-call <code>action\_token</code> that is never re\-armed automatically \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/13](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/13)\)\.
* amt\_media \- new module attaching and detaching IDE\-R virtual media\, so a bootable ISO and a writable answer\-file image can be served to a bare\-metal machine in one session \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20)\)\.
* amt\_media \- new module that attaches a bootable read\-only ISO and/or a writable answer image over IDE\-R\, and detaches a previously attached session\. An IDE\-R session is a long\-lived process\, so <code>state\=attached</code> forks a detached background daemon that owns the connection\, writes a small JSON state/receipt file keyed by <code>session\_id</code>\, and returns once that daemon has reported success or an early failure\; <code>state\=detached</code> looks the daemon up by the recorded pid and asks it to stop\. Credentials reach the daemon only as in\-memory arguments across the fork \-\- never via argv or the environment\, since no process is ever spawned or exec\'d \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/7](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/7)\)\.
* amt\_redirection \- new module that reports Intel AMT redirection\-service support\, enablement\, and TCP reachability as three separate signals\, and optionally mutates enablement via <code>AMT\_RedirectionService\.RequestStateChange</code>\; read\-only by default and never attaches or streams media \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/13](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/13)\)\.
* docs/capability\-matrix\.md gains a fourth tier for firmware\-verified claims and tabulates the six defects hardware qualification found that neither the unit nor the mock tier could have caught\.

* plugins/module\_utils/media\_session\.py \- the detached\-session lifecycle this module builds on\: double\-fork daemonization\, an atomically\-written state file\, pid\-liveness\-based staleness recovery\, and pre\-spawn media validation shared between check mode and real attach \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/7](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/7)\)\.
* plugins/module\_utils/redirection\.py \- add <code>RedirectionSession\.set\_recv\_timeout\(\)</code> \(so a long\-lived caller can wake periodically without busy\-polling\) and <code>peer\_certificate\_sha256\(\)</code> \(best\-effort TLS peer fingerprint\, mirroring <code>tls\.peer\_certificate\_evidence\(\)</code> for the WS\-Man transport\) \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/7](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/7)\)\.
* plugins/module\_utils/redirection\_service\.py \- WS\-Man view of redirection\-service capability/enablement plus an injectable TCP reachability probe\, kept separate from the stateful IDE\-R/SOL session transport \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/13](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/13)\)\.
* roles/amt\_baremetal\_install \- new reusable role that drives a complete unattended bare\-metal install lifecycle \(validate \-\> probe \-\> attach media \-\> arm one\-time boot \-\> reset \-\> observe \-\> wait for hand\-off \-\> detach\) on top of amt\_info\, amt\_power\, amt\_boot\, amt\_redirection\, and amt\_media\. Asserts the play targets exactly one host \(delegate\_to\: localhost does not stop inventory fan\-out\)\, requires an explicit confirm\_destructive\=true before doing anything destructive\, runs preflight capability checks via amt\_info before any mutation\, persists resumability state per target so an interrupted run never blindly re\-arms one\-time boot or re\-issues a reset of uncertain outcome\, and always detaches media via block/rescue/always even on failure\. Supports both an ider\_cdrom \(IDE\-R virtual media\) and a native pxe boot provider\, mutually exclusive by construction \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/9](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/9)\)\.
* tests/hardware \- add the eight\-stage hardware qualification playbooks \(qualify\_readonly\, qualify\_checkmode\, qualify\_power\, qualify\_media\_attach\, qualify\_writable\_image\, qualify\_pxe\, qualify\_idempotent\_reprobe\)\, an inventory\.yml\.example with obviously fake values\, and a README documenting the gating\, staged ordering rationale\, and the manual KVM/MEBx recovery path to keep reachable before running the media\-attach stage for the first time\. qualify\_readonly\.yml and qualify\_checkmode\.yml are the two filenames the CircleCI hardware workflow already references \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/11](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/11)\)\.
* tests/hardware \- every stage 4\-7 playbook \(<code>qualify\_power</code>\, <code>qualify\_media\_attach</code>\, <code>qualify\_writable\_image</code>\, <code>qualify\_pxe</code>\) now has the same block/rescue pattern <code>qualify\_readonly\.yml</code> already used\, surfacing <code>error\_class</code>/<code>endpoint</code>/<code>operation</code>/ <code>indeterminate</code> on failure instead of a <code>no\_log</code>\-censored\, undiagnosable one\. <code>roles/amt\_baremetal\_install</code>\'s own rescue \(used by stages 5 and 7\) does the same before re\-raising\, so a firmware failure inside the role is diagnosable too\. A new <code>amt\_qualify\_attended</code> variable \(default <code>true</code>\) gates every interactive <code>ansible\.builtin\.pause</code> in these playbooks\, so they can run unattended in CI \-\- where <code>pause</code> would otherwise block forever on stdin the machine executor cannot supply \-\- with the corresponding approval job acting as the human checkpoint instead\.
* tests/hardware \- support qualifying several machines\, each with its own credentials and its own reviewed TLS fingerprint\, via a numeric variable suffix \(<code>AMT\_HOST\_2</code>\, <code>AMT\_PASSWORD\_2</code>\, <code>AMT\_TLS\_FINGERPRINT\_2</code>\)\. Ports stay shared\, since AMT always listens on the same ones\. Per\-machine pins are required rather than optional\, because each endpoint presents its own self\-signed certificate and a shared fingerprint would surface as a pin mismatch rather than a configuration error\.
* tests/hardware/make\-test\-media\.sh \- new script that provisions the small bootable ISO \(iPXE\'s own <code>ipxe\.iso</code>\) and zero\-filled writable raw image stages 5 and 6 need\, entirely inside the workspace\. Idempotent and safe to re\-run\; fails loudly rather than producing a placeholder file if the download fails or a size check does not land on a multiple of 512 bytes\.
* tests/hardware/qualify\_pxe\.yml \- assert that <code>AMT\_BootSettingData</code> reads back unchanged after the one\-time PXE boot\'s reset\, in addition to confirming the arm reads back armed and the reset is issued and recovered\. Documented plainly\, in both the playbook and <code>tests/hardware/README\.md</code>\, that this does not read Intel AMT\'s internal one\-shot \(<code>IsNextSingleUse</code>\) role bit \-\- no module in this collection exposes a getter for it \-\- and that netboot succeeding is outside this playbook\'s authority to verify\, since it depends on DHCP/boot\-service infrastructure this collection cannot observe\.
* tests/hardware/qualify\_writable\_image\.yml \- weaken the \"bytes actually landed on disk\" assertion\. A BIOS sitting at a boot prompt does not spontaneously write to an attached floppy\, so <code>bytes\_written\=0</code> \(nothing booted on the target to issue a write\) is now reported as a legitimate\, expected outcome rather than a failure\. What is still asserted every run\: the image is accepted and attached\, and the device is presented to the guest as writable \(the MODE\_SENSE write\-protect bit is <code>0x00</code>\, not <code>0x80</code>\)\. A non\-zero <code>bytes\_written</code> is still cross\-checked against the on\-disk checksum\, since that combination disagreeing would be a real bug\.

<a id="breaking-changes--porting-guide"></a>
### Breaking Changes / Porting Guide

* amt\_boot\, amt\_redirection\, amt\_media \- the <code>intel\-amt\-operation/v1</code> receipt \(<code>schema</code>\, <code>action</code>\, <code>endpoint</code>\, <code>previous</code>\, <code>desired</code>\, <code>observed</code>\, <code>tls\_peer\_fingerprint</code>\, and the success\-path <code>error\_class</code>\) is now nested under an <code>operation</code> key on every module\, matching the shape <code>amt\_power</code> already used\. It was previously spread directly at the top level of these three modules\' results\, which meant a caller could not write one helper that reads <code>error\_class</code>/<code>tls\_peer\_fingerprint</code> from any module in the collection \-\- exactly the defect tracked as issue \#22\. Module\-specific return values \(for example <code>amt\_boot</code>\'s <code>device</code>/<code>boot\_config\_selector</code>/<code>boot\_source\_selector</code>\, <code>amt\_redirection</code>\'s <code>supported</code>/<code>enabled</code>/<code>transport\_reachable</code>\, and <code>amt\_media</code>\'s <code>session\_id</code>/<code>session\_state</code>/<code>devices</code>/<code>bytes\_read</code>/<code>bytes\_written</code>\) are unaffected and remain at the top level\. A failed module\'s result is unaffected by this change\: <code>error\_class</code> still surfaces at the top level of <code>fail\_json</code>\, since that is what Ansible itself surfaces and what rescue blocks read via <code>ansible\_failed\_result\.error\_class</code>\.
* amt\_info \- now returns a non\-secret <code>intel\-amt\-operation/v1</code> receipt under an <code>operation</code> key\, for parity with the other four modules\. It is read\-only \(<code>operation\.action</code> is always <code>get\_facts</code>\, <code>operation\.changed</code> is always <code>false</code>\)\, and <code>operation\.previous</code>/<code>operation\.desired</code>/<code>operation\.observed</code> are always <code>null</code> \-\- a read has no prior\, intended\, or separately\-observed state to report beyond what the existing <code>amt</code> return key already carries\.

<a id="security-fixes"></a>
### Security Fixes

* IDE\-R write payloads are bounded against the transfer length declared by the WRITE CDB\, and MediaImage refuses any write that would extend the backing file\. Previously a host could declare a small write\, pass the bounds check\, then stream unbounded DATA\_FROM\_HOST frames at an advancing offset and grow a local file \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14)\)\.
* The insecure\-transport gate is enforced in the <code>WsmanClient</code> constructor rather than only in the convenience classmethod\, so plaintext WS\-Man cannot be selected without explicitly setting <code>allow\_insecure\_transport\=true</code> regardless of which entry point is used \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/12](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/12)\)\.
* The redirection session refuses to downgrade to cleartext or cnonce\-less digest authentication\, and verifies a pinned TLS leaf certificate before transmitting any bytes \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14)\)\.
* amt\_media \- require O\(tls\_fingerprint\) when O\(use\_tls\=true\)\, and reject O\(ca\_path\) outright\. The redirection plane is a raw TLS socket whose only trust mode is leaf pinning\; TLS without a pin is encrypted but unauthenticated\, and silently ignoring a supplied ca\_path would leave an operator believing the session was chain\-validated \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20)\)\.
* amt\_media \- session state files are created mode 0600 rather than at the umask default\, so they are not readable by other local users even when the runtime directory already exists with laxer permissions \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20)\)\.

<a id="bugfixes"></a>
### Bugfixes

* CI \- pin ansible\-core to 2\.17 in the hardware qualification job\. The lab runner image ships Python 3\.10 and ansible\-core 2\.19 requires 3\.11\+ on the controller\, so the job would have failed at dependency installation\. 2\.17 is also the collection\'s declared floor\, so hardware qualification now exercises the oldest version the collection claims to support\.
* CI \- the publish job reads <code>GALAXY\_API\_KEY</code>\, matching the name actually stored in the <code>galaxy\-publish</code> context\. It previously read <code>ANSIBLE\_GALAXY\_API\_KEY</code> and would have failed on its first real run\.
* Collection staging derives its build root from the repository path\, so concurrent checkouts on one host no longer clobber each other\'s staged tree \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/14)\)\.
* Exclude repository tooling from the built collection artifact\. <code>renovate\.json</code> was being shipped to consumers\; <code>CODE\_OF\_CONDUCT\.md</code> and <code>SECURITY\.md</code> are now excluded too\.
* Mock WS\-Man fixture server \- answer <code>Enumerate</code> for <code>AMT\_BootCapabilities</code>\, not only <code>Get</code>\. Unit tests mock enumeration directly\, so this was invisible until a real integration target sent a real <code>Enumerate</code> \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/pull/20)\)\.
* Omit WS\-Man method parameters whose value is <code>None</code> instead of emitting an empty element\. Real AMT 16\.1\.30 rejects <code>CIM\_BootConfigSetting\.ChangeBootOrder</code> carrying an empty <code>\<Source/\></code> with HTTP 400 and \"The supplied SOAP violates the corresponding XML schema definition\"\, because <code>Source</code> is typed as an endpoint reference and so requires child elements\. This blocked IDE\-R and BIOS boot entirely against real firmware\.
* README \- fix the unattended\-install example playbook referencing C\(media\.operation\.session\_id\)\, which does not exist\: M\(james\_crowley\.intel\_amt\.amt\_media\) returns RV\(session\_id\) at the top level of its result\, not nested under an C\(operation\) key \(that nesting is specific to M\(james\_crowley\.intel\_amt\.amt\_power\)\)\. Corrected to C\(media\.session\_id\) in both the boot\-arming and detach tasks \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/10](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/10)\)\.
* Support Python 3\.10 on the controller\, which the collection already claimed by declaring <code>requires\_ansible \'\>\=2\.17\.0\'</code> \(ansible\-core 2\.17 runs on 3\.10\) but did not actually honour\. <code>client\.py</code> imported <code>enum\.StrEnum</code> and <code>media\_session\.py</code> used <code>datetime\.UTC</code>\, both Python 3\.11\+\, so every module that imports the client raised ImportError on 3\.10 before any error handling could classify it\.
* <code>PowerAction</code> keeps <code>StrEnum</code> semantics via an explicit <code>\_\_str\_\_</code>\. A plain <code>\(str\, Enum\)</code> renders as <code>PowerAction\.ON</code> under <code>str\(\)</code> and f\-string interpolation rather than <code>on</code>\, which would have silently changed the shape of messages and receipt fields\.
* amt\_baremetal\_install \- <code>amt\_baremetal\_install\_host</code> no longer defaults to <code>inventory\_hostname</code>\. AMT answers on a separate management address from the operating system\'s hostname\, so that default silently pointed at the wrong endpoint or an unresolvable name\; it now resolves from <code>amt\_host</code> and otherwise stays unset so validation fails loudly\.
* amt\_baremetal\_install \- choose the power transition from the observed power state instead of always issuing <code>reset</code>\. A master bus reset does nothing to a machine that is already off\, so installing an operating system onto a powered\-off machine \-\- arguably the common bare\-metal case \-\- attached the media\, armed the one\-shot boot\, and then reported success having booted nothing\.
* amt\_baremetal\_install \- connection variables now fall back to the conventional <code>amt\_\*</code> inventory variables \(<code>amt\_host</code>\, <code>amt\_password</code>\, <code>amt\_tls\_fingerprint</code> and friends\) that this collection\'s README\, docs and example inventory all use\, so a conventional inventory drives the role with no per\-variable mapping\.
* amt\_info \- read the system UUID from <code>CIM\_ComputerSystemPackage\.PlatformGUID</code>\. It was read as <code>UUID</code> from <code>CIM\_ComputerSystem</code>\, which has no such property\, so it was null on every endpoint and silently disabled the identity cross\-check that guards against acting on the wrong machine \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/30](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/30)\)\.
* amt\_info \- render the system UUID in the canonical dashed form\, reversing the first three SMBIOS fields\. <code>PlatformGUID</code> arrives as 32 undashed hex characters with those fields little\-endian\, so the naive reading produces a plausible\-looking UUID that does not match what MEBx displays \-\- which would make the identity cross\-check fail against a correctly recorded expectation \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/32](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/32)\)\.
* amt\_info \- report the AMT firmware version from <code>CIM\_SoftwareIdentity</code> \(the instance whose <code>InstanceID</code> is <code>AMT</code>\, read from <code>VersionString</code>\)\. It was previously read from <code>AMT\_GeneralSettings\.Version</code> and <code>AMT\_SetupAndConfigurationService\.VersionsSupported</code>\, neither of which exists\, so the reported version was always null \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/18](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/18)\)\.
* amt\_info \- stop reading <code>CIM\_ComputerSystem</code> during facts gathering\. It existed only to source the UUID and contributed nothing else\, so removing it also saves a WS\-Man round trip per call\.
* amt\_power \- correct the documentation example\, which used <code>state\: on</code>\. YAML parses an unquoted <code>on</code> as the boolean <code>true</code> rather than the string <code>\"on\"</code>\, so anyone copying the example would have passed the wrong type and failed argument validation\.
* tests/hardware/qualify\_power\.yml \- restore the power state the stage started from\. It previously left the target powered off\, and the next stage issues a reset\, which does nothing to an off machine\.
* tests/hardware/qualify\_power\.yml \- restore the starting power state using <code>previous\_state</code>\, the key <code>amt\_power</code> actually returns\. It referenced a non\-existent <code>power\_state</code> key\, so the guard always evaluated to <code>unknown</code>\, the restore silently skipped on every run\, and the stage reported that it had left the machine as\-is\. An assertion now fails loudly if the starting state cannot be read\.
* tests/hardware/qualify\_readonly\.yml \- surface the redacted failure detail when amt\_info fails\. The task carries <code>no\_log\: true</code> to keep task arguments \(including the password\) out of the log\, but that also censored the module\'s own error\, which errors\.py has already redacted and which is therefore safe to show\. A censored failure is undiagnosable\, so a rescue now reports <code>error\_class</code>\, <code>endpoint</code>\, <code>operation</code>\, <code>indeterminate</code> and the redacted message\.
* tests/hardware/qualify\_writable\_image\.yml \- pass the full connection options when re\-reading a media session\'s byte counters\. The call omitted <code>tls\_fingerprint</code> and the redirection port\, so it failed with <code>error\_class\=tls\_validation</code> after the writable\-device assertion had already passed\.
* tests/hardware/render\-inventory\.sh \- emit credentials as <code>lookup\(\'ansible\.builtin\.env\'\, \.\.\.\)</code> expressions instead of literal values\, so the AMT password and TLS fingerprint never touch disk\. Also accept <code>AMT\_HOST</code>\, <code>AMT\_PORT</code> and <code>AMT\_REDIRECTION\_PORT</code>\, matching the variables the lab context provides\.
* tests/hardware/render\-inventory\.sh \- emit the <code>amt\_targets</code> group the qualification playbooks actually target\. It previously emitted <code>amt\_lab</code>\, so every play would have matched zero hosts and reported success having done nothing\.
* tests/integration/mock\_servers/wsman\_server\.py \- AMT\_BootCapabilities now answers Enumerate as well as Get\. amt\_boot\'s discover\_and\_validate\(\) and redirection\_service\.py\'s get\_capabilities\(\) both reach it via Enumerate\+Pull \(it has no natural instance key for a Get SelectorSet\)\; the mock only implemented the Get form used by amt\_info\'s facts\-gathering path\, which every prior unit test masked by mocking WsmanClient\.enumerate\(\) directly instead of exercising this server \([https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/8](https\://github\.com/james\-crowley/ansible\-collection\-intel\-amt/issues/8)\)\.
