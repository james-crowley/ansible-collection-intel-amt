# Development and CI tooling. CI installs from THIS file (see the `lint` job in
# .circleci/config.yml), so a contributor who runs `pip install -r
# requirements-dev.txt` is running exactly the linter versions that will judge
# the pull request.
#
# Pinned exactly, on purpose. Unpinned linters make the outcome of a lint run a
# function of when it happened: a new ruff release adding or widening a rule
# turns main red with no code change, and a contributor whose cache happens to
# hold an older release sees a green local run and a red CI run (or worse, the
# reverse). Measured example: ruff 0.15.5 reports S603 in
# tests/unit/plugins/module_utils/test_media_session.py and
# tests/unit/plugins/modules/test_amt_media.py, ruff 0.16.0 does not.
#
# Bumping these is a deliberate act: change the pin, run the full local
# sequence in CONTRIBUTING.md, and fix (or justify) whatever the new version
# finds -- in the same pull request. Renovate proposes these bumps one at a
# time; see renovate.json.
#
# Runtime and test-run dependencies live elsewhere and are NOT duplicated here:
#   requirements.txt                    -- controller runtime (requests)
#   tests/unit/requirements.txt         -- what ansible-test units installs
#   tests/integration/requirements.txt  -- what ansible-test integration installs
